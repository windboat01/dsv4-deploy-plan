一、总体架构

1.1 分层架构

Android System Telecom Framework Telephony Framework (InCallService) (TelecomManager) | Application Layer RecorderApplication - Logcat.init() - DynamicColors - Notifications.updateChannels() - Preferences.migrate() | InCallService Layer RecorderInCallService - onCallAdded() entry point - Call.Callback() state changes - startRecording() create RecorderThread - requestStopRecording() cancel recording - updateForegroundState() notification update | Recording Thread Layer RecorderThread - run() thread entry - evaluateRules() rule matching - recordUntilCancelled() core recording - encodeLoop() encoding loop | Format / Codec Layer Format (Opus/AAC/FLAC/WAV/AMR) - Encoder: MediaCodecEncoder / PassthroughEncoder - Container: MediaMuxerContainer / WaveContainer | Output / File Layer OutputDirUtils, OutputFilenameGenerator CallMetadataCollector, Retention

二、应用启动流程

RecorderApplication.onCreate() 执行初始化：

  • Logcat.init() — 初始化日志系统
  • 未捕获异常处理器 — 崩溃保存到文件
  • DynamicColors — Material You 动态颜色
  • Notifications.updateChannels() — 创建通知频道
  • Preferences 迁移: migrateTemplate, migrateAudioSource, migrateRecordRules

应用不需要用户主动打开。系统在来电/去电时自动绑定 InCallService。

三、通话生命周期管理

3.1 RecorderInCallService

继承 InCallService，系统框架自动绑定。

onCallAdded(call): 入口点

  • call.registerCallback(callback)
  • handleStateChange(call, null)

Callback 定义：

  • onStateChanged(call, state) -> handleStateChange(call, state)
  • onDetailsChanged(call, details) -> handleStateChange(call, null) (三星兼容)
  • onCallDestroyed(call) -> requestStopRecording(call)

状态机：

  • STATE_ACTIVE -> startRecording(call)
  • STATE_DIALING -> if pref enabled, startRecording(call)
  • STATE_DISCONNECTED -> requestStopRecording(call)
  • STATE_HOLDING -> set isHolding = true

startRecording() 前置检查：call recording enabled, permissions, not duplicate, call package. 然后创建 RecorderThread 并启动。

3.2 三星固件兼容

三星固件 onCallRemoved() 可能不被调用。BCR 在 onDetailsChanged() 中额外检查通话状态，实现双重保险。

四、音频捕获引擎

4.1 RecorderThread

构造函数从 Preferences 读取格式、采样率、音频源配置。sources 数组决定创建几个 AudioRecord 实例。

AudioSourcesources说明
VOICE_CALL[VOICE_CALL]1个 AudioRecord，双向
VOICE_UPLINK_DOWNLINK[UPLINK, DOWNLINK]2个，立体声
VOICE_UPLINK[VOICE_UPLINK]仅你的声音
VOICE_DOWNLINK[VOICE_DOWNLINK]仅对方声音

4.2 run() 主循环

run()
  1. startLogcat()
  2. evaluateRules()         规则匹配
  3. if cancelled -> return
  4. createFileInDefaultDir()
  5. recordUntilCancelled()  核心录音
  6. Os.fsync()
  7. FINALIZING: 移动到输出目录或删除
  8. processRetention()      清理过期文件
  9. stopLogcat()
  10. onRecordingCompleted()

4.3 AudioRecord 初始化

minBufSize = AudioRecord.getMinBufferSize(SR, MONO, PCM16BIT)

for source in sources:
    AudioRecord(source, sampleRate, MONO, PCM16BIT, minBufSize * 6)

audioRecords.forEach { it.startRecording() }
encoder = format.getEncoder(getMediaFormat(), getContainer(fd))
encoder.start()
encodeLoop(audioRecords, encoder, minBufSize)

minBufSize * 6 = 6倍最小缓冲区，用来应对 MediaCodec 编码波峰。

4.4 encodeLoop() 核心循环

while (!isCancelled || !buffersFlushed):
    1. AudioRecord.read(NON_BLOCKING)     关键: 非阻塞读
    2. interleaveChannels()               多源交错
    3. 纯静音检测 (全零检查)
    4. encoder.encode(bufferOut)          编码
    5. buffersIn.compact() + bufferOut.clear()
    6. bufferOverruns 超限检测
    7. DISCARD_TOO_SHORT -> KEEP 升级
    8. 睡眠到 "缓冲区半满"

encoder.encode(bufferOut, true)            EOF

关键参数: AudioRecord.READ_NON_BLOCKING — 避免三星通话结束后永久阻塞。

十二、边缘情况处理

12.1 三星通话结束不通知

onCallRemoved() 不被调用。BCR 在 onDetailsChanged() 和 handleStateChange() 中双重检测 DISCONNECTED 状态。

12.2 三星 AudioRecord 永久阻塞

通话结束后 VOICE_CALL 不再产生数据。使用 AudioRecord.READ_NON_BLOCKING 避免永久挂起。这是今天我们的方案卡住的核心原因。

12.3 VOICE_CALL 单流限制

系统只有一个 VOICE_CALL 音频流，多个同时进行的通话会混合。

12.4 编解码波峰

minBufSize * 6 缓冲区 + bufferOverruns 计数器。

12.5 Direct Boot

设备未解锁时输出到 filesDir/，解锁后自动迁移。

12.6 纯静音丢弃

全零 PCM 检测，发现后抛 PureSilenceException 删除文件。

十三、对我们的关键启示

13.1 InCallService + VOICE_CALL + CAPTURE_AUDIO_OUTPUT 是正确方案

不需要 root 额外 API、不需要 MODIFY_AUDIO_SETTINGS、不需要 su。

13.2 READ_NON_BLOCKING 是必需的

// 正确:
audioRecord.read(buf, 0, buf.length, READ_NON_BLOCKING)

// 错误 (默认阻塞，三星通话结束后永久挂起):
audioRecord.read(buf, 0, buf.length)

13.3 可以复用 BCR 的编码循环

在 encodeLoop 中增加 LocalSocket 并行推流，不需要重写 AudioRecord 层。

13.4 CAPTURE_AUDIO_OUTPUT 必须在 manifest 声明

仅放在 privapp-permissions XML 中不够 — 今天踩了 6 小时坑的教训。

14.2 关键社区议题

议题 #530: VOICE_CALL 在部分设备上输出纯静音 (58条评论)

最热门的 open issue。某些 AOSP 定制 ROM 上 VOICE_CALL 源不输出音频。chenxiaolong 确认是 ROM/固件层面 bug，BCR 无法解决。

对我们: Pixel 7a 已验证正常工作。

议题 #709: 现代 Android 通话录音机制的限制

  • 网络切换中断录音: 3G->VoLTE/VoWiFi 时 VOICE_CALL 流断开不重连
  • 振铃音不可录: Android 15+ 上不行
  • VOICE_CALL vs VOICE_UPLINK+VOICE_DOWNLINK: 双源方案更复杂但某些设备更可靠

议题 #695: Google Phone 应用冲突

Google Phone 独占 InCallService。BCR 通过 Magisk 系统 app 可绕过。

议题 #39: 多通话录音重叠 (53条评论)

共享 VOICE_CALL 流，多个通话线程捕获相同混音。
