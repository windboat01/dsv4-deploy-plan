三、通话生命周期管理

3.1 核心类：RecorderInCallService

继承 InCallService，系统框架自动绑定。

Entry: onCallAdded(call: Call)

onCallAdded(call)
  - call.registerCallback(callback)
  - handleStateChange(call, null)    // 处理当前状态（可能是 ACTIVE）

Callback

private val callback = object : Call.Callback() {
    override fun onStateChanged(call, state)
        handleStateChange(call, state)

    override fun onDetailsChanged(call, details)
        handleDetailsChange(call, details)
        handleStateChange(call, null)  // 三星兼容

    override fun onCallDestroyed(call)
        requestStopRecording(call)
}

状态机

handleStateChange(call, state):
    STATE_ACTIVE     -> startRecording(call)
    STATE_DIALING    -> if (prefs.recordDialingState) startRecording(call)
    STATE_DISCONNECTED -> requestStopRecording(call)
    STATE_HOLDING    -> callsToRecorders[call]?.isHolding = true

startRecording()

private fun startRecording(call: Call) {
    // 前置检查：
    // 1. prefs.isCallRecordingEnabled
    // 2. Permissions.haveRequired()
    // 3. callsToRecorders.containsKey(call) 防重入
    // 4. callPackage 检查

    val recorder = RecorderThread(this, this, call)
    callsToRecorders[call] = recorder
    notificationIdsToRecorders[id] = recorder
    updateForegroundState()
    recorder.start()
}

3.2 三星固件 Bug 兼容

三星固件的两个已知问题：

  • onCallRemoved() 可能不被调用
  • 通话断开的唯一通知渠道：onDetailsChanged() 中传递 DISCONNECTED 状态

BCR 在 onDetailsChanged() 中额外调用 handleStateChange()，双重保险。

3.3 通知动作

ACTION_PAUSE   -> recorder.isPaused = true
ACTION_RESUME  -> recorder.isPaused = false
ACTION_RESTORE -> recorder.keepRecording = KEEP
ACTION_DELETE  -> recorder.keepRecording = DISCARD

4.2 run() 主循环

run()
  1. startLogcat()
  2. evaluateRules()
  3. if (isCancelled) -> return
  4. createFileInDefaultDir()

4.3 recordUntilCancelled() — AudioRecord 初始化

val minBufSize = AudioRecord.getMinBufferSize(SR, MONO, PCM16BIT)

for (source in sources) {
    val audioRecord = AudioRecord(
        source, sampleRate, MONO, PCM16BIT,
        minBufSize * 6,         // 6倍缓冲区！应对编码波峰
    )
}

audioRecords.forEach { it.startRecording() }

val encoder = format.getEncoder(
    format.getMediaFormat(sources.size, sampleRate, formatParam),
    format.getContainer(pfd.fileDescriptor)
)
encoder.start()
encodeLoop(audioRecords, encoder, minBufSize)

4.4 encodeLoop() — 核心编码循环

while (!isCancelled || !buffersFlushed):

    阶段1: AudioRecord.read(NON_BLOCKING)
    阶段2: interleaveChannels() — 多源交错
    阶段3: 纯静音检测（全零检查）
    阶段4: encoder.encode(bufferOut) — 编码
    阶段5: buffersIn.compact() + bufferOut.clear()
    阶段6: 超限检测 bufferOverruns++
    阶段7: 最短录音检查 DISCARD_TOO_SHORT -> KEEP
    阶段8: 睡眠到"缓冲区半满"

encoder.encode(bufferOut, true)  // endOfStream=true

关键参数：AudioRecord.READ_NON_BLOCKING — 三星通话结束后不会永久阻塞。BCR 在文档中明确标注这是处理三星设备的关键兼容性代码。

十二、边缘情况处理

12.1 三星通话结束不通知

onCallRemoved() 不被调用。BCR 在 onDetailsChanged() 和 handleStateChange() 中双重检测 DISCONNECTED 状态。

12.2 三星 AudioRecord 永久阻塞

通话结束后 VOICE_CALL 不再产生数据。
关键：使用 AudioRecord.READ_NON_BLOCKING 避免永久挂起。

12.3 系统只有一个 VOICE_CALL 流

多个通话同时进行时，VOICE_CALL 包含所有通话的混合音频。

12.4 编解码器波峰

minBufSize * 6 的大缓冲区 + bufferOverruns 计数器。

12.5 Direct Boot

设备未解锁时输出到 filesDir/，解锁后自动迁移到用户目录。

12.6 通知限速

Android 限 10 次/秒。BCR 使用旧状态缓存，仅变化时更新。

12.7 文件写入失败

先写临时文件再 moveToOutputDir()，moveError 捕获并通知用户。

12.8 纯静音丢弃

编码循环中逐帧检查全零PCM，发现后抛 PureSilenceException 删除文件。

12.9 Ignore 规则

cancel() -> 线程直接退出，不创建任何文件。

12.10 暂停/保持丢弃

继续采集但不编码，帧计数增加但编码帧数不变。

十三、对我们的关键启示

13.1 正确的通话捕获路径

InCallService + AudioRecord(VOICE_CALL) + CAPTURE_AUDIO_OUTPUT — 这是标准方案。不需要 root 额外 API、不需要 MODIFY_AUDIO_SETTINGS、不需要 su。

13.2 READ_NON_BLOCKING 是必需的

// 错误：阻塞读，三星通话结束后永久挂起
audioRecord.read(buf, 0, buf.length)

// 正确
audioRecord.read(buf, 0, buf.length, READ_NON_BLOCKING)

13.3 可以复用 BCR 的录音循环

在 encodeLoop 中增加一个并行流：通过 LocalSocket 将 PCM 数据发送到 ADB forward。不需要修改 BCR 的核心逻辑。

13.4 AndroidManifest 必须声明

CAPTURE_AUDIO_OUTPUT 和 CONTROL_INCALL_EXPERIENCE 必须在 APK manifest 中声明。仅放在 privapp-permissions XML 中不够——今天踩了6小时坑的教训。
